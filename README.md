## 如何开始

1. 打开上方网页，在“实验种子”填写数字或点“随机种子”。
2. 展开“模型连接设置”，填写模型服务商的 API 地址、Key 和模型名；可获取模型列表，也可手动填模型名。
3. 如需使用其他推理框架，在“推理框架”面板载入 JSON 文件，或直接编辑框架 JSON；内置示例可直接运行。
4. 点“开始实验”，再选择“移动、采集或休息”，最后点“发送操作”。
5. 查看纯文本交互记录和框架状态。失败时本轮应保持原状态和原时间，可重试同一动作；命令记录可按步骤回放并导出快照。

API Key 默认只留在当前网页内存中。勾选“记住Key”才会保存在本机浏览器存储；发起推理请求时 Key 会发送给你选择的模型服务商。共享电脑不要勾选。静态页面没有服务器替用户保管密钥。

## 网页包含什么

- 岛屿研究者地图、细分区、资源点和鼠标悬停位置的六向文字观察。
- 模拟时钟、局部降雨、温度、潮位、水源、资源和生态账本。
- 单人实验种子、模型连接配置、固定动作选择、文本回合记录与身体系统示例推理。
- `data.js` 保存场景数据；`model.js` 处理世界时间和库存；`observation.js` 生成位置与方向观测；`app.js` 管理界面；`survival-agent.js` 协调单人生存回合；`framework-runtime.js` 运行通用人体推理框架；`body-framework.js` 保存内置示例状态和规则。

## 模型边界

岛屿岸线和粗高程参考公开资料；细分网格、资源位置与数量、天气细节和生物生态参数包含模拟设定。种群和食源账本用于展示生态变化，不代表Olorua实测数量或野外承载力。人物身体状态不由岛屿模块计算。模型服务、浏览器跨域限制或无效响应可能使回合失败；页面使用者应确认失败回滚后再重试，避免把演示结果当成医学结论。

## 检查

需要 Node.js，无第三方依赖。岛屿观测检查：

```sh
node tools/observation-check.js
```

此前曾通过 JavaScript 语法检查和 `git diff --check`；这些不能代替真实模型 API 的端到端回合验证。请在组内有可用 API Key 后手动完成至少一轮成功操作和一轮失败重试，并确认模拟时间只在成功回合后推进。

## 接手

接手时先读项目外层 `AGENTS.md` 和 `readme.md`，再查看 `SPEC.md`。保持“本岛证据、代理资料、模拟假设”分开，不将模拟参数写成实地调查结果。源代码变更要同步更新本 README 和相关 `docs/` 主题说明。

## 维护与发布网站

网站源码在本仓库根目录；GitHub Pages 从 `main` 根目录发布，线上地址为 [岛屿观测台](https://2024-dada.github.io/SITP-text-survival/)。改动地图或实验界面时：

1. 先检查当前分支和工作区，再同步 `main`；从最新主线创建 `codex/简短任务名` 分支，避免覆盖已有修改。
2. 只修改完成任务需要的文件；同步更新本 README、`SPEC.md` 和相关主题文档。不要提交 API Key、访问令牌或带密钥的截图/日志。
3. 使用仓库已有的检查并记录实际结果。语法检查通过不代表浏览器交互或模型 API 已验证；没有实际运行的项目必须保留待验状态。
4. 用户要求发布后，合并到 `main` 并查看 GitHub Pages 部署状态。部署完成后刷新线上地址，确认新功能真实显示，再把状态写成“已上线”。合并成功但部署/页面未核实，仍标记为待验证。
5. GitHub Release 是固定版本归档，不是 Pages 网站；除非用户明确要求，不创建 Release、不改网址、不删除旧归档。

线上异常通过新的 Git 提交或 PR 修复/回退，不强制覆盖主线历史。长期规则及项目总进度见项目外层 `AGENTS.md` 和 `readme.md`。
