## 如何开始

以下操作对应线上 v4.2 Agent 文本交互工作区。

1. 网站启动时自动载入随站的 A/B/C 参数参考 Agent。展开右侧“参数观测与岛屿视图”可查看，也可手动更换 Olorua JSON systems；内置身体示例不会自动当作岛屿数据。
2. 展开“模型连接设置”，填写模型服务商的 API 地址、Key 和模型名；可获取模型列表，也可手动填模型名。
3. 页面会显示全部已载入 Agent，且每轮都强制启用。可选填一句本轮任务（发送给全体），然后点主区“运行第一轮”或“运行第 N 轮”。留空时 Agent 按各自 rule 和状态交流。
4. Agent 在一轮内并行处理同一份起始状态。成功后查看公开发言、定向消息、状态变化前后值和理由；工具调用与失败原因折叠查看。
5. 下一轮所有 Agent 会看到上一轮完整对话。失败时状态不提交，可重试同一轮。结束会话并重置会清除当前会话状态，保留已载入 JSON。

API Key 默认只留在当前网页内存中。勾选“记住Key”才会保存在本机浏览器存储；发起推理请求时 Key 会发送给你选择的模型服务商。共享电脑不要勾选。静态页面没有服务器替用户保管密钥。

## 网页包含什么

- 岛屿研究者地图、细分区、资源点和鼠标悬停位置的六向文字观察。
- 模拟时钟、局部降雨、温度、潮位、水源、资源和生态账本。
- 求生者与岛屿 Agent 的逐轮文本交互、模型连接配置、JSON 参数观察、逐项状态变更审计。
- `data.js` 保存旧场景演示数据；`model.js` 处理世界时间和库存；`observation.js` 生成位置与方向观测；`app.js` 管理岛屿观测界面；`survival-agent.js` 协调 Agent 聊天和保留的单人生存原型；`framework-runtime.js` 运行通用推理框架；`body-framework.js` 保存旧版内置身体示例（不会自动当成岛屿 JSON）。

## 模型边界

岛屿岸线和粗高程参考公开资料；细分网格、资源位置与数量、天气细节和生物生态参数包含模拟设定。种群和食源账本用于展示生态变化，不代表 Olorua 实测数量或野外承载力。当前 Agent 会话默认使用用户提供的 A/B/C 参数参考 JSON，也可手动换载岛屿组更新稿；文件中的待确认状态不因自动载入而变成人工验收。A、B、C 系统规则各含 166,656、34,326、94,771 个字符的数据快照，模型上下文容量和调用成本尚未实测。网站不猜岛屿或身体参数，求生者 Agent 初始无身体参数。模型服务、浏览器跨域限制或无效响应可能使回合失败；代码已设计为整轮不提交并允许重试，实际 API 与浏览器交互仍待人工验收。
