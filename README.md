## 如何开始

以下操作对应 Agent 文本交互工作区。

1. 网站启动时自动载入随站的 A/B/C 参数参考 Agent。展开右侧“参数观测与岛屿视图”可查看，也可手动更换 Olorua JSON systems；内置身体示例不会自动当作岛屿数据。
2. 在页面最上方的“模型连接”面板填写 API Key、选择或确认服务商，再从自动读取的列表选择模型；列表不可用时可手动填写模型名。Base URL、连接检查、余额和记住Key也都在该面板。同济用户勾选“同济大学 AGI”；ModelGo Key 会自动填入官方地址并读取模型。
3. 页面会显示全部已载入 Agent，且每轮都强制启用。可选填一句本轮任务（发送给全体），然后点主区“运行第一轮”或“运行第 N 轮”。留空时 Agent 按各自 rule 和状态交流。
4. Agent 在一轮内并行处理同一份起始状态。成功后查看公开发言、定向消息、状态变化前后值和理由；工具调用与失败原因折叠查看。
5. 左侧计数器记录本次会话累计发生的 Agent 工具对话轮次，悬停可看各 Agent 的数量；重试中发生的轮次也计入。网页保留完整对话；下一轮发给模型的历史最多 8000 字符，过长时只发送最近内容。失败时状态不提交，可重试同一轮；已生成的分段输出会显示在失败记录中。结束会话并重置会清除当前会话状态和计数器，保留已载入 JSON。
6. 每轮 Agent 推理后，底部报告会对照本轮任务、全部 Agent 输出和参数状态，按时间线汇总各项行动；缺少精确数据时仍给出标明依据的模拟估计。报告显示抽样结果、点位、天气、活动前后景象、岛屿状态结算和人体 Agent 中文感受；感受与报告正文只供研究者查看，不写入下一轮。下一轮收到结构化的时钟、位置、天气、水量、资源总量、生态指标、行动结果及物品参数。每项行动按15分钟步长结算；可映射到现有库存的采集才扣减资源。报告完整后才提交状态，失败可以重试。
7. 页面底部继续显示实验模拟参数。系统卡片随已应用的框架与成功回合刷新；每个数值参数都显示单位，注册表未解释的编号项会注明缺少释义，推定单位会标出“推定”。

API Key 默认只留在当前网页内存中。勾选“记住Key”才会保存在本机浏览器存储，所选平台、Base URL 和模型名也会一并保存。发起推理请求时 Key 会发送到填写的 Base URL 所属服务；只填写可信服务商的官方地址。共享电脑不要勾选。静态页面没有服务器替用户保管密钥。

## 网页包含什么

- 岛屿研究者地图、细分区、资源点和鼠标悬停位置的六向文字观察。
- 页面底部的行动地图与事件报告；逐项展示本轮时间线、活动抽样结果、点位与天气、前后场景、状态结算和人体 Agent 中文感受。研究者给出日程时报告逐项对应，不再只选一个代表事件。
- 模拟时钟、局部降雨、温度、潮位、水源、资源和生态账本。
- 求生者与岛屿 Agent 的逐轮文本交互、模型连接配置、JSON 参数观察、逐项状态变更审计。
- `data.js` 保存旧场景演示数据；`model.js` 处理世界时间和库存；`observation.js` 生成位置与方向观测；`app.js` 管理岛屿观测界面；`survival-agent.js` 协调 Agent 聊天和模型连接；`framework-runtime.js` 运行通用推理框架；`monitor.js` 从运行时读取参数并绘制底部监控卡片；`body-framework.js` 保存旧版内置身体示例（不会自动当成岛屿 JSON）。

## 模型边界

岛屿岸线和粗高程参考公开资料；细分网格、资源位置与数量、天气细节和生物生态参数包含模拟设定。种群和食源账本用于展示生态变化，不代表 Olorua 实测数量或野外承载力。当前 Agent 会话默认使用用户提供的 A/B/C 参数参考 JSON，也可手动换载岛屿组；文件中的待确认状态不因自动载入而变成人工验收。A、B、C 系统规则各含 166,656、34,326、94,771 个字符的数据快照；它们与本轮起始状态会完整提供给模型，所选模型的输入上下文窗口仍需实测。交互历史最多发送 8000 字符，工具历史向模型保留最近4轮、每个工具结果最多2400字符；单次模型输出分别限制为首段1800、续写1200 tokens，续写和工具对话均不设固定轮数上限。逐次响应会在当前网页会话中保存并拼接，左侧计数器记录工具对话轮次。求生者 Agent 初始无身体参数；人体 Agent 的中文感受由本轮真实框架参数、statement 与行动结果整理，定性体验不等同于新增的数值体征。模型服务、浏览器跨域限制或无效响应可能使回合失败；报告未完成时岛屿时间与资源结算保持暂存，可重试。真实 API 与跨组联调仍待人工验收。
