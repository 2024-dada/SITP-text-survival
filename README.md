## 如何开始

以下操作对应 Agent 文本交互工作区。

1. 网站启动时自动载入随站的 A/B/C 参数参考 Agent。展开右侧“参数观测与岛屿视图”可查看，也可手动更换 Olorua JSON systems；内置身体示例不会自动当作岛屿数据。
2. 展开“模型连接设置”，粘贴 ModelGo Key 即自动填入官方地址并读取模型；同济用户勾选“同济大学 AGI”即可使用其官方地址。其他服务可在服务商菜单中选择，或填写文档给出的 Base URL 和模型名称。“测试连接 / 获取模型”可重新读取 `/models`；如果服务商没有该接口，仍可手动填写模型名称。高级地址可修改，不会把 Key 发送到多个服务商尝试。
3. 页面会显示全部已载入 Agent，且每轮都强制启用。可选填一句本轮任务（发送给全体），然后点主区“运行第一轮”或“运行第 N 轮”。留空时 Agent 按各自 rule 和状态交流。
4. Agent 在一轮内并行处理同一份起始状态。成功后查看公开发言、定向消息、状态变化前后值和理由；工具调用与失败原因折叠查看。
5. 下一轮所有 Agent 会看到上一轮完整对话。失败时状态不提交，可重试同一轮。结束会话并重置会清除当前会话状态，保留已载入 JSON。
6. 滚到页面底部查看实验模拟参数。系统卡片随已应用的框架与成功回合刷新；编号参数若原注册表未提供解释，会注明“注册表未附具体释义”。

API Key 默认只留在当前网页内存中。勾选“记住Key”才会保存在本机浏览器存储，所选平台、Base URL 和模型名也会一并保存。发起推理请求时 Key 会发送到填写的 Base URL 所属服务；只填写可信服务商的官方地址。共享电脑不要勾选。静态页面没有服务器替用户保管密钥。

## 网页包含什么

- 岛屿研究者地图、细分区、资源点和鼠标悬停位置的六向文字观察。
- 模拟时钟、局部降雨、温度、潮位、水源、资源和生态账本。
- 求生者与岛屿 Agent 的逐轮文本交互、模型连接配置、JSON 参数观察、逐项状态变更审计。
- `data.js` 保存旧场景演示数据；`model.js` 处理世界时间和库存；`observation.js` 生成位置与方向观测；`app.js` 管理岛屿观测界面；`survival-agent.js` 协调 Agent 聊天和模型连接；`framework-runtime.js` 运行通用推理框架；`monitor.js` 从运行时读取参数并绘制底部监控卡片；`body-framework.js` 保存旧版内置身体示例（不会自动当成岛屿 JSON）。

## 模型边界

岛屿岸线和粗高程参考公开资料；细分网格、资源位置与数量、天气细节和生物生态参数包含模拟设定。种群和食源账本用于展示生态变化，不代表 Olorua 实测数量或野外承载力。当前 Agent 会话默认使用用户提供的 A/B/C 参数参考 JSON，也可手动换载岛屿组更新稿；文件中的待确认状态不因自动载入而变成人工验收。A、B、C 系统规则各含 166,656、34,326、94,771 个字符的数据快照，模型上下文容量和调用成本尚未实测。网站不猜岛屿或身体参数，求生者 Agent 初始无身体参数。模型服务、浏览器跨域限制或无效响应可能使回合失败；代码已设计为整轮不提交并允许重试。工具调用不设固定往返上限，若模型不结束工具循环会继续产生 API 请求；实际 API 与跨组联调仍待人工验收。

1. 先检查当前分支和工作区，再同步 `main`；从最新主线创建 `codex/简短任务名` 分支，避免覆盖已有修改。
2. 只修改完成任务需要的文件；同步更新本 README、`SPEC.md` 和相关主题文档。不要提交 API Key、访问令牌或带密钥的截图/日志。
3. 使用仓库已有的检查并记录实际结果。语法检查通过不代表浏览器交互或模型 API 已验证；没有实际运行的项目必须保留待验状态。

5. GitHub Release 是固定版本归档，不是 Pages 网站；除非用户明确要求，不创建 Release、不改网址、不删除旧归档。
