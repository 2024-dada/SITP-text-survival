## 1. 结论摘要

同一位置的北、东、南不再共用一段岸滩/坡度/鱼贝文字。以 `(294,-52)` 为例：旧版北、东、南三张卡的五行动植物/坡度/海岸/鱼影/贝类文字逐字相同；新版三向分别关联海域 111/14/73，岸线最近出口 14/8/12 米，鱼影分别为零散/较多/零散，南向还因距离超过 60 米不再写礁缝贝类。以 `(270,0)` 和 `(81,253)` 为例，旧版北与东的核心五行也逐字相同；新版北与东分别关联不同的海域斑块，给不同的岸线距离、鱼影观察结果和朝向描述。南/西改为内陆抬升与遮挡，不再出现“朝海”段落。

允许真实相似的环境得到相似文字：例如 `(150,150)` 南、西都沿同一道岸后坡向上抬升，二者仍可能都写“持续向上抬升”；这不是四向强制改写。差异必须来自方向采样事实，不靠同义词随机替换。

本轮代码复核还修正了三类边界：局部岸线可由通过遮挡检查的侧向射线发现；斜向陆地/海域目标按各自视线裁决，中心线挡住时不再一概隐藏或显示；地图日志合并同日同类幼体成熟记录并保留资源点编号。鼠标滚轮以指针为锚点缩放，复位只改视口，不推进世界或改观察位置/库存。

## 2. 原问题与真实原因

| 现象 | 原实现中的真实原因 |
|---|---|
| 北、东、南整段相同 | `observation.js` 的 `marine(s,p,w)` 汇总观察点 85 米内所有 R05/R06/R07，只要该方向 65 米内到岸，就把同一段鱼贝文字追加到每张卡。方向没有参与资源选择。 |
| 四向都写“明显倾斜” | `local()` 的 `slope=Math.hypot(terrain(+2)-h, terrain(+2)-h)/2` 只有坡度大小，没有方向；阈值 `slope>.24` 在多数岸边/林坡都成立。`terrain()` 还有 `×min(1, edgeDist/35)` 的海岸高程衰减，近岸 35 米内被压向 0，形成人工陡坡，进一步放大了该阈值。 |
| 岸线距离和形态粗 | 旧 `observe()` 只沿中心射线每 5 米判断 `inside()`，没有左右射线，也不说明岸线是横过、向左斜还是向右斜。 |
| 鱼贝一圈复用 | 同上；`marine()` 不读取方向，只按观察点距离 85 米取并集，再在 `edge<=65` 时整段追加。 |
| 资源绕过遮挡泄露 | 旧方向目标只筛 `dot>=.65`（约 49 度）和距离，没有检查观察点到目标本身的视线；`block` 只用于过滤中心射线上的目标。 |
| 近岸小景物矛盾 | `local()` 的 `shrub=field(...)`、`rock=field(...)` 不按生物群系缩放，光秃岸滩也可能出现“密集灌丛/大量石砾”。 |
| 背景重复 | 雨势、夜间、强雨提示在每张方向卡里各写一遍；脚下又把 `marine()` 写一遍，同一片海在多个位置重复。 |
| 资源中心/耗尽判断不稳 | 方向卡用 `local(s,斑块中心)` 的混合权重描述，邻近斑块库存可能掩盖目标斑块耗尽；脚下使用整个半径内的混合资源，容易把十几米外的斑块说成“脚边”。 |
| 变化记录重复且难定位 | 不同资源点每天分别写一条同类成熟记录，短时间推进大量日期时容易刷屏，且每条只有“R06有1个幼体成熟”不易追查。 |

## 3. 现在的观测流程

`observation.js` 现在按下列顺序工作，算法标识 `obs-dir-v4`：

1. **唯一世界状态**：只读 `state.sites` 的库存；观察不写回，不生成第二份资源。
2. **位置场**：`surface(p)` 按生物群系缩放树冠、灌草、石砾、落叶，并给出冠层高度；`local(p)` 另外计算天气、湿润和斑块加权线索。
3. **方向扫描**：每张水平卡沿中心线每 5 米采样，记录距离层、岸线出口、首个遮挡和坡面趋势；分档为0—10米、10—40米、40米以上，因此中景首个采样点通常为15米、远景首点为45米。方向射线遇到遮挡后停止记录该方向更远的景物。
4. **结构化事实**：方向、岸线中心/扇区最近距离、遮挡距离与原因、坡度种类和数值、海域斑块编号/距离/角差、陆地目标编号。事实只用于研究和复核，不直接全部交给角色。
5. **可见性与归属筛选**：陆地斑块和海域斑块都按角差归给最近的一张卡，并逐个检查目标视线；海岸线另检查中心及左右各12度的视线。中心方向受阻不代表整张扇区都受阻，只有仍看得见的斜向目标才可出现；斜角对象只允许在相邻卡补一句“视野边缘”，不复制细节。
6. **文字投影**：先写公共背景一次，再由方向事实选择近/中/远景、坡度、岸线/遮挡、陆地和海域线索。没有事实差异时不换同义词。

## 5. 参数与边界

| 项目 | 取值 | 性质 |
|---|---:|---|
| 水平卡半角 | ±50 度 | 模拟视域；四卡在斜角有 10 度重叠 |
| 近景 | 0—10 米 | 分档阈值；每5米采样，从5米开始，不要求每层都写 |
| 中景 | 10—40 米 | 首个采样点通常为15米 |
| 远景 | 40 米以上，最多到可辨上限 | 首个采样点通常为45米 |
| 陆地斑块起点 | 15 米 | 15 米内交给“脚下”，减少脚下与方向卡重复 |
| 陆地斑块最远 | 70 米 | 只描述可辨认的候选线索 |
| 遮挡判定 | 地形+冠层 > 眼高+2.5 米，且距离≥20 米；资源另检查自身视线 | 简化二维高程/冠层遮挡，不是逐树三维追踪 |
| 坡度采样 | 0、10、20、30、40、50、60 米 | 粗 DEM 线性趋势；不是米级测绘 |
| 岸线射线 | 中心、左 12 度、右 12 度，取最近出口 | 模拟几何；不是实测岸线宽度 |

| 鱼影讨论距离 | ≤120 米 | 超过只写水面反光 |
| 贝类/甲壳类讨论距离 | ≤60 米 | 更远不写礁缝细节 |
| 退露贝类潮位 | ≤0.15 米 | 模拟条件 |
| 甲壳类潮位 | ≤0 米 | 独立条件 |

## 6. 近岸资源关联与唯一库存

旧版把“锚点”当成鱼的位置，导致方向卡只能整圈汇总。新版明确区分：

- **锚点**：`data.js` 中含 R05/R06/R07 的 57 个资源地带，是“岸边作业入口/近岸资源地带”的位置，不是鱼的真实坐标。
- **海域范围**：每个锚点投影到最近岸线，再向海一侧偏移约 9 米，得到半径 12—26 米的模拟范围。它只用于判断“哪一段岸外与这个锚点相关”，不是新增渔场。
- **库存**：海域范围只读取原锚点 `state.sites[id].pools` 的同一份库存；观察、文字、试采都指向这一份。没有为海域另建库存，也没有在格子里重复发放。
- **归属**：观察时计算每片海域与四张水平卡的角差，只让角差最小的卡主述；同一片海不会在北、东、南三张卡里各写一遍。距离超过 120 米只写水面反光，超过 60 米不写礁缝贝类/甲壳类细节。
- **线索与库存分离**：有库存不一定见鱼；见鱼不等于能抓到；没有鱼影不清零库存；库存耗尽后对应线索才消失。鱼、贝、甲壳类各自读取自己的库存和潮位条件，不整段捆绑。

## 10. 旧版对照与斜角对象

## 11. 已知不足

1. 约 90 米 DEM + 38 个高程点仍是粗插值；坡度的方向和档位可复核，但不是米级测绘。海岸高程衰减仍会在近岸制造一段较陡的抬升，文字已改为保守措辞，但没有重做高程模型。
2. 树冠是连续场和生物群系高度估算，不是逐棵树的三维遮挡；林间空隙、树干位置和真实冠层透光没有建模。
3. 海域范围是“锚点投影 + 固定偏移/半径”的模拟设定，不代表真实鱼礁、潮下地形或鱼群活动范围；120/60 米讨论距离也是可校准阈值。
4. 鱼影观察机会是固定种子+3 小时时段的可见性模型，不是鱼类行为；同一时段内反复观察稳定，但跨时段会变化。
5. 斜角对象采用“一卡主述 + 相邻卡一句边缘提示”，不是两张卡都完整描述。若复核认为需要两卡都写细节，可在 `observe()` 第二遍增加，但会增加重复。
6. 真实对称地形仍可能得到相似文字，例如 `(150,150)` 南/西都沿同一道岸后坡向上；本轮不把“四向永不相同”当验收标准。
7. 这是静态观测台，不接人物身体、行动裁决、火/加工、空间记忆或服务器；资源数量仍是丰富实验情景，不是本岛普查。
8. 浏览器检查使用 headless Chrome 和模拟鼠标事件，未测试触屏；移动端布局只做了响应式 CSS 检查，未逐机型验证。
9. 外层三篇阶段二正式说明待发布完成后同步；发布前以代码仓库 `docs/` 为准。
